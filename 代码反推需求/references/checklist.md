# 交付自检

交付前逐条过。任一项不通过则修正。

## 一、禁令（代码标识）

- [ ] 无类名、方法名、包名、文件名、行号、局部变量名
- [ ] 无代码片段、注解、方法签名
- [ ] 无方法级调用链叙述（"A 调用 B 再调用 C"），已改写为业务步骤或接口时序
- [ ] 无 ORM 映射注解与实体类名

## 二、技术内容完整性（不得缺失）

- [ ] 有业务流程图（主干 + 逆向），且配文字说明
- [ ] 有状态机图、ER 图
- [ ] 涉及跨系统的有接口时序图
- [ ] 有架构图与部署说明
- [ ] 接口契约完整：路径、方法、鉴权、幂等、限流、超时、请求字段、响应字段、错误码
- [ ] 数据库完整：表用途、字段（业务名+真实名）、类型、必填、默认值、枚举、主键、唯一约束、索引、关联、分片、事务边界
- [ ] 中间件完整：缓存的键规范/过期/失效/降级、消息的触发/内容/幂等/重试、定时任务的频率/扫描条件/失败处理
- [ ] 幂等与并发：幂等键、并发场景、锁、被拦时的用户可见表现
- [ ] 外部依赖：超时、失败表现、是否阻断、重试降级、补正方式
- [ ] 配置项：默认值、取值范围、影响分支、生效方式、环境差异
- [ ] 公式：变量来源、精度舍入、边界、算例
- [ ] 时效：计时起点、时长、边界包含性
- [ ] 非功能：性能、安全、可观测性、发布回滚
- [ ] 中间件产品与实例细节已放入附录 B，正文未滥用

## 三、呈现约定

- [ ] 库表首次出现为「业务名（真实名）」格式
- [ ] 同节后续引用可省略真实名，未出现歧义
- [ ] 接口字段表同时给出业务名与真实字段
- [ ] 附录 B 有中间件实例清单与键规范、topic、定时表达式

## 四、业务详细度

对每个功能自问：**没看过代码的测试，能否据此写出用例？**

- [ ] 前置条件明确（状态、数据、时间窗口）
- [ ] 每个输入项的必填、格式、范围、特殊规则齐全
- [ ] 每个判断的分支写全，含默认分支与其他取值
- [ ] 每个分支有结果和用户可见表现
- [ ] 多个校验并存时写明了判断顺序与先报哪条
- [ ] 失败场景与提示原文齐全
- [ ] 涉及金额、数量、比例的有公式、精度、算例
- [ ] 涉及时间的有计时起点、时长、边界包含性
- [ ] 受配置影响的写明了配置项、默认值、影响分支

## 五、完整度

- [ ] 业务对象、角色、状态、枚举都有全量清单
- [ ] 逆向流程已覆盖
- [ ] 系统自动触发的行为（定时、过期、回调）已覆盖
- [ ] 异常与人工介入路径已覆盖
- [ ] 外部依赖失败时的表现已覆盖
- [ ] 隐含行为 10 项已逐条核对
- [ ] 写库后的读取端已找到并写明
- [ ] 已知限制与不支持场景已写明

## 六、可判定性

- [ ] 每条规则可用"是/否"判定
- [ ] 无"可能""通常""一般"等模糊表述；确需不确定性时用置信度标注
- [ ] 无未定义术语，首次出现处已解释
- [ ] 同一事物全文用同一个词
- [ ] 编号连续无重复，引用处编号正确

## 七、结构

- [ ] 章节顺序符合模板，未自行增删章节
- [ ] 每个功能都能在功能索引中找到
- [ ] 所有图语法合法（Mermaid 可渲染）
- [ ] 待确认清单与正文标记对得上

## 八、交付说明

必须主动告知：
- 覆盖哪些模块，排除哪些
- 待确认事项数量与分布
- 推断项数量（哪些需业务方核对）
- 未读取或读取不充分的部分
- 中间件与外部依赖中，哪些内容无法从代码确认
