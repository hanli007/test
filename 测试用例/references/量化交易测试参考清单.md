## 二、xlsx 之外的补充项（本文件唯一不可替代的价值）

以下 13 条来自历次分析推导，**任何一份 xlsx 里都查不到**。生成用例时若涉及对应业务，需一并考虑。

### 搬砖套利

- **提币额度/内部转账优先路径**：搬砖资金在两所间流转应优先走交易所间内部快速转账，链上提币仅作补充——否则资金效率会被链上确认时间严重拖累。xlsx 只有「提币/链拥堵场景」，未涉及路径选择本身。
- **交易所维护窗口时间差导致的假价差**：两所维护窗口通常不同步。A 所维护期间若价差计算仍引用 A 所旧报价（未及时冻结或标记不可用），会产生虚假套利信号。需验证维护期间价差计算源是否自动切换/冻结，而不只是「维护期间拦截下单」。
- **反向价差瞬间归零后的残留敞口**：单腿已成交、另一腿因价差瞬间收窄未按预期价格成交时，残留敞口除「回滚」外还应有「以更差价格强制对冲止损」的兜底路径。xlsx 的「单边成交补偿」表述较笼统。
- **税务/合规成本是否纳入净利计算**：不同司法辖区规则不同，可作待确认项。

### 期现套利

- **基差为负（贴水）场景**：xlsx 隐含升水场景（现货多+合约空）。基差为负（合约更贵，常见于极端下跌）时是否支持反向套利，还是只支持单方向——这是等价类划分的遗漏，应补「贴水」「升水」两类。
- **移仓时资金费结算时间对齐**：前一合约结算与新合约建仓时点未对齐，会在移仓瞬间出现双重资金费或资金费缺失窗口。
- **交割结算价计算窗口内的风险**：结算价通常是一段时间的加权平均而非单点价格。该窗口内的价格操纵风险与流动性不足风险需单独验证；xlsx 只验证「到期后归零」。

### 资金对冲

- **对冲工具流动性枯竭导致敞口扩大**：极端行情下合约端想减仓但深度不足，中性策略被迫承受敞口扩大。与 xlsx 的「极端行情脱钩」角度不同——脱钩是价格关系失效，这里是执行层面无法平仓。
- **多腿对冲建仓的原子性**：现货与合约两腿若不能在同一事务内完成，一腿已成、另一腿失败的中间态如何回滚。xlsx 有「强平联动」（已建仓后的风险联动），但没有「建仓过程本身不同步」。
- **稳定币脱锚引发的连锁强平**：作为抵押品的稳定币脱锚后，抵押价值重估会触发一连串保证金不足强平。xlsx 只到「重估抵押价值」，未到系统性传导。

### 横跨性

- **多策略共享账户的资金竞争**：搬砖/对冲/闪兑等策略共享同一资金账户时，策略 A 占用资金会导致策略 B 的套利机会因余额不足而错过。xlsx「资金占用与周转」提及但未细化为策略间抢占。
- **策略暂停/恢复时执行中操作的中断点一致性**：人工紧急暂停某策略时，正在执行的多腿操作是等待完成还是立即中断？中断点的资金/持仓状态能否恢复到一致态？
- **套利类策略对延迟建模应更悲观**：xlsx「成本建模」的延迟要求（100~500ms）对套利类偏乐观。搬砖等策略对延迟极度敏感，「回测能赚钱、实盘抢不到」的落差远大于方向性策略，应对这类策略用更严格的悲观延迟假设。

## 三、参考领域 → 用例模块的映射

选型时按下表决定启用哪个一级模块/分组（**该映射 xlsx 里没有**）：

| xlsx 领域 | 对应用例模块 | 说明 |
|---|---|---|
| 撮合引擎 | 功能逻辑-现货 / 功能逻辑-合约 | 通用撮合概念放现货；保证金、强平、资金费、ADL 放合约 |
| 风控与清算 | 功能逻辑-合约（深化） | 净值/保证金率/分级强平/ADL 属合约特有 |
| 安全与防欺诈 | 独立一级模块「风控」 | 与现货/合约分组里已有的自成交、刷单场景**去重**，不要两处都建 |
| 资金与钱包 | 功能逻辑-资金/提现 分组 | 链上资产相关，若业务纯所内划转则本类不适用 |
| 监控与可观测 | 分散到各分组的「预期结果」 | 告警、日志、埋点作为业务用例的预期项，不单独建模块 |
| 合规与审计 | 独立一级模块「风控」 | 审计留痕、权限分级 |
| API 与接口 | 不单独成模块 | 幂等、重试、限流已分散到各业务用例 |
| 多端与体验 | 按项目实际端决定 | 纯后端策略系统通常不适用 |
| 回测防作弊 | 独立分组「回测」 | 仅策略回测系统需要 |
| 性能/容灾/数据质量 | 视项目范围 | 非功能测试，多数需求文档不涉及，按需启用 |

- `ref_query.py` 必须放在 `~/PycharmProjects/tc-refs/` 执行。放在 skill 目录下执行会被终端执行管控拦截（exit 137）。
